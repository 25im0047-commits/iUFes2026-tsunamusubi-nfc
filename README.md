# iUFes2026 システムプロトタイプ

iU FesのNFCスタンプラリーを動作確認するTanStack Startプロトタイプです。本リポジトリはiU Fesの周遊企画を扱います。他の企画・公式サイトはそれぞれ別リポジトリで管理します。

良いおばけ9体・悪いおばけ2体の構成、会話、晴天・雨天の配置、景品受け取り場所を、2026-10-04までの確認に合わせています。10月5日に届いた通常絵11枚・スタンプ絵11枚をローカルへ反映しています。画面はプロトタイプで、未発見のおばけはCSSによる仮表示を維持します。会場図はCanvaの背景画像を基に表示しますが、最終パンフレットの完成版ではありません。アンケートは端末内保存まで実装済みで、運営への送信・自動集計は未実装です。

## デザイン

提供された「iUFes2026 おばけMap デザイン案.html」を基準に、全画面の配色・文字・丸いカード・立体ボタンを統一しています。マップの演出はスタンプ数に応じて強まり、スタンプ取得時は全画面の光・フラッシュ・紙吹雪・跳ねる文字と画像・発光する進捗表示を組み合わせます。`prefers-reduced-motion: reduce` のときは点滅と動きを停止します。晴天の会場図は10月8日の提供資料を反映しています。NFC取得条件・保存キー・会話内容は維持しています。

添付HTMLに含まれるDela Gothic OneとZen Maru GothicのWOFF2サブセットを`public/fonts`から配信します。外部フォント配信へは接続しません。収録外の文字は端末の標準フォントで表示します。著作権表示とライセンスは`public/fonts/OFL.txt`に同梱しています。

## 実装フロー

1. パンフレットのQRからWebページへアクセスし、タイトルを表示
2. あそびかたを読んでMapへ進む（開始済みの場合はMap、全取得済みの場合は完了画面へ）
3. NFCタグに書かれたURL（例：`https://example.com/?id=good-01`）をスマートフォンの標準機能で開く
4. URLの`id`でおばけを特定し、処理後に`id`だけを削除（他のクエリとハッシュは保持）
5. 良いおばけとの会話終了でスタンプを`localStorage`へ保存
6. 良いおばけ9体をすべて集めると、暗転・2つの影の演出を経てMapに悪いおばけを表示
7. メデューサ（4問）・ヴァンパイア（5問）を順不同で訪問。各質問は初期状態で必須（管理画面で個別に任意へ変更可能）。DB保存成功後にスタンプを取得
8. 全11体の取得でエンディングを表示し、入口のTV対面壁側にある景品受け取り場所で画面を見せてプレゼントを受け取る。クイズなし
9. 取得済みカードでは会話を再表示できる。回答の上書き・スタンプの二重取得は行わない

景品提示画面の「受け取りを完了する（スタッフ用）」は、取り消せない旨を確認してから受取済みを端末に記録します。以後は引き換え画面を表示しません。ただし端末ストレージの削除・別端末による再引き換えを防ぐ仕組みではありません。

`/admin` では質問文（空欄不可・300文字以内）と質問ごとの必須設定、回答の一覧・詳細・おばけ別絞り込み・削除・CSV出力が可能です。選択肢・回答形式・質問IDや回答内容の編集はありません。質問文は共有DBに保存し、参加者へ初期表示・30秒ごと・画面復帰時に反映します。CSVは絞り込み条件に一致する全ページを出力し、見出しには現在の質問文を使用します。UTF-8 BOM付きで、数式と解釈されうる文字列には先頭へアポストロフィを付けます。未回答は空欄、0点は0です。回答削除は参加者のスタンプ・受取済み記録に影響せず、再送でも回答を復活させません。新規回答のみDBへ保存し、過去の端末内回答は自動送信しません。DB保存失敗時は取得を止め、同じ回答を再送します。

質問文の専用テーブルは `iufes2026_question_texts`。既存環境でも `scripts/init-surveys.mjs` を再実行して追加します。すでに編集した文章・必須設定・回答を初期値で上書きしません。

プロトタイプ用に、参加者ページ最下部と管理画面へ「この端末の進捗をリセット」を設置しています。確認後、そのブラウザーのスタンプ・旧移行データ・下書き・送信待ち・景品受取済み・匿名参加者IDを削除します。別タブの参加者画面も再読み込みし、古い進捗の復活を防ぎます。管理画面はログイン状態を維持します。DBの回答と共有設定は残し、次の回答は新しい匿名参加者IDで保存します。本番運営で二重引き換えを防ぐ機能ではありません。

質問・回答テーブルの初期化：Node 24で `node --env-file=.env.local scripts/init-surveys.mjs`。専用テーブルは `iufes2026_question_rules`・`iufes2026_survey_receipts`・`iufes2026_survey_answers`。回答本文の削除後も重複送信を防ぐ受付記録（匿名ID・おばけID・送信内容のハッシュ・日時）は残します。他企画のテーブルは変更しません。

NFCタグのURLは `https://公開ドメイン/?id=good-01` の形式です。`?good-01` だけではIDを指定したことになりません。URLを開くだけでは取得せず、会話終了ボタンでスタンプを保存します。同じページ内で別のID付きURLへ移動した場合も会話を開き、`id`だけを削除します。

Mapの配置は、パスワード付きの `/admin` で運営が切り替えます。天気の自動判定や参加者による切替は行いません。1Fは提供されたアイコンなしの会場図に透過おばけ・景品アイコンを重ね、晴雨ごとの位置を切り替えます。2F・3Fの会場図と位置は両配置で共通です。1Fに表示する屋外設置のおばけは屋外タブへ重複表示しません。設定は共用Tursoの専用テーブルへ保存し、初期値をページのSSRと一緒に取得することで、表示後にマップだけが配置APIの返答を待つ時間をなくします。1F背景も先読みします。表示中30秒ごと・画面復帰時の再取得は維持。以前の端末内天気設定は参照せず、通信失敗時は警告します。

## 管理画面の設定

VercelのProductionに `TURSO_DATABASE_URL`・`TURSO_AUTH_TOKEN`・`ADMIN_USER`・`ADMIN_PASSWORD` を登録してください。今回の管理用ID・パスワードは依頼者の承認により既存のすみだサイトと同じ設定を使用します。接続情報を `VITE_` 付きの変数へ入れないでください。Previewから本番設定を変更させないため、同じ本番DB接続情報をPreviewへ配布しません。

新環境のテーブル初期化はNode 24で `node --env-file=.env.local scripts/init-weather.mjs` を実行します。今回の共用Tursoでは初期化済みです。専用テーブルは `iufes2026_weather`（晴雨設定1行）と `iufes2026_admin_limits`（管理APIの試行制限）で、他の企画のテーブルは使用しません。初期配置は晴天です。

管理用認証情報はHTTPSの管理APIにのみ送信し、ブラウザーの永続ストレージへ保存しません。各API呼出しで認証し、ログアウト・再読み込み後は再ログインが必要です。入力値・同一オリジンを検証し、管理APIは全体で毎分20回までに制限します。複数の運営端末が同時変更した場合は、最後に保存された設定が有効です。

悪いおばけは、良いおばけ9体の全取得前には直接URLでも開けません。解放前はMapで案内し、解放後に現地で再タッチします。URLを開いただけ、会話を途中で閉じただけでは取得しません。

進捗と完了した回答は、同じブラウザー・同じオリジンの`localStorage`にも保存します。読み込み時に不正データを除去し、全対象IDの取得を達成条件とします。端末への保存失敗時は警告と再試行ボタンを表示し、画面内の進捗・回答を保持します。別タブの更新と画面復帰時には保存済み進捗を合成します。端末間同期・不正防止・自動集計は提供していません。

保存形式はv3です。選択肢の固定IDと会話完了記録を使い、表示文言や回答の不備で取得済みスタンプを取り消しません。v2の完了回答・スタンプは引き継ぎ、それ以前の「悪いおばけ訪問済み」は完了に変換しません。旧5体版タブの保存から新しいスタンプを守るため、保存先を `iufes2026-system-prototype-progress-v3-confirmed-20261004` へ分離します。新キーがなければ旧v3キー、旧v3もなければさらに古いキーから読み取り、新キーへ保存します。旧キーと旧データは変更・削除しません。未対応の保存形式・質問版を検出した場合は上書きを止めます。移行手順と制約は[参加者フロー](docs/participant-flow.md)を参照してください。

## キャラクター画像

10月5日10:58 JSTに狩俣ひよりさんが[通常絵とスタンプ絵を共有](https://iu-people.slack.com/archives/C0BPYFKPZFA/p1791165519921949)しました。通常絵は `public/ghosts/characters/<slug>.png`、スタンプ絵は `public/ghosts/stamps/<slug>.png` に置きます。各11枚、原本は354 × 472pxの透明RGBA PNGです。

会話・タイトル・悪いおばけの解放・獲得済み図鑑には背景透過の通常絵、取得演出にはスタンプ絵を使います。未発見の図鑑はCSSによる仮表示を維持します。画像参照と表示範囲は `src/lib/artwork.ts` で定義します。

PNG原本は加工せず保持します。`src/lib/artwork.ts` に、アルファ値が0ではない画素の外接矩形へ8pxの余白を加えたSVGの `viewBox` を登録し、透明な余白による表示サイズの違いを調整します。通常絵とスタンプ絵はそれぞれの表示範囲を使います。

黒猫Aに赤い目の絵、Bに青い目の絵を対応させるのはローカル表示用の仮割当です。色と台詞・タグID・設置場所の対応は確定根拠がなく、運営へ確認中です。[素材の原本と対応表](docs/slack-confirmed-content-20261004.md#10月5日の画像納品)を参照してください。

## 起動とローカル確認

```bash
npm ci
npm run dev
```

Node.js 22.12.0以上を使用してください。起動後は[タイトル](http://localhost:3001/)と[黒猫Aの会話](http://localhost:3001/?id=good-01)を同じPCのブラウザーで確認できます。会話を終えたら、取得演出と獲得済み図鑑がスタンプ絵になることを確認します。悪いおばけのURLは良い9体を集めてから開きます。

ローカル検証後、承認済みの作業ブランチへcommit・pushします。最終SHAの必須CIが成功し、最終レビューで問題がないことを確認してから、PRをreadyにしてmainへmergeします。手動デプロイやVercelの権限変更は行いません。`localhost` の確認結果は実機NFCや公開先の動作確認とは別です。実機のNFC確認には、端末からアクセスできるHTTPS環境を用意します。

```bash
npm run typecheck
npm test
npm run build
```

PRとmainへのpushでは、GitHub ActionsでWindows/Linux、Node.js 22.12.0/24のチェックと、Linux / Node 24のChromium・WebKitブラウザーテストを実行します。ブラウザーテストの起動方法は[開発手順](CONTRIBUTING.md)を参照してください。各PRのChecksで結果を確認してください。

## 公開時の参考手順

以下は手動公開を別途依頼された場合の参考です。今回の作業は、承認済みブランチへのpushとCI・レビュー後のmergeまでです。

このアプリはTanStack StartのSSRを使用します。`vite.config.ts`のNitroプラグインが、Vercelで実行するサーバー関数と静的ファイルを生成します。`vercel.json`でフレームワークを`tanstack-start`に指定しています。

1. VercelでこのGitリポジトリをImportします。Root Directoryはリポジトリ直下（`package.json`がある場所）です。
2. Framework Presetが **TanStack Start** であることを確認します。Build Command / Output Directoryの独自のOverrideは解除し、フレームワークの既定値を使ってください。Node.jsはCIでも検証する **24.x** を推奨します。
3. デプロイすると、Vercelが割り当てる`https://<project-name>.vercel.app`で公開できます。独自ドメインの購入・DNS設定は不要です。現状のアプリに必須の環境変数はありません。
4. 公開URLの`/`でタイトルが表示され、`/?id=good-01`で会話が開くことを確認します。NFCタグにはProductionに割り当てた同じドメインのURLを書き込みます。進捗はオリジン単位なので、Preview URLとは共有されません。

すでに404が発生しているプロジェクトは、この修正をコミット・pushし、修正を含むコミットから再デプロイしてください。古いコミットのRedeployだけでは修正が入りません。

`dist`や`dist/client`を静的サイトとして配信しても、このSSRアプリのトップページは生成されません。Vercel用ビルドでは`.vercel/output/config.json`と`functions`・`static`が生成されます。`/index.html`へのSPA用rewriteは不要です。HTMLの生成元は`src/routes/__root.tsx`であり、リポジトリ直下に別の`index.html`を置くとNitroが空のHTMLを配信する原因になります。

設定の根拠：[Vercel公式のTanStack Startデプロイ手順](https://vercel.com/kb/guide/deploy-a-tanstack-start-app-to-vercel)。ローカルでの本番ビルド・配信確認は[開発手順](CONTRIBUTING.md)を参照してください。
