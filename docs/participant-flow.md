# 参加者フローと回答仕様

更新日：2026-10-05。対象：iU FesのNFCスタンプラリー。

## 決定の根拠

依頼者が提示した「画面表示の流れ.pdf」（2ページ）、確認回答、9月28日以降のSlack・Canvaの確定内容に基づきます。画面・質問・完了条件をこの文書に、キャラクター・配置・素材の根拠を[確定内容](slack-confirmed-content-20261004.md)に記録しています。

依頼者による確定事項：

- スタンプ取得は会話終了時。
- 良いおばけ9体と悪いおばけ2体、計11体。
- 悪いおばけのアンケートはあり。クイズなし。
- 景品は受付ではなく、入口のTV対面壁側にある景品受け取り場所で受け取る。
- 晴天と雨天の配置は別々に扱い、当日の状態に合わせて手動で切り替える。
- 回答の扱いは実装側の判断に委任。
- 解放前の悪いおばけのNFCアクセスは不可。
- 悪いおばけ2体は順不同。複雑な例外導線は作らない。

以下の「回答仕様」は、委任を受けて今回採用した実装方針です。旧Slack SSOTの「受付クイズへ進む」等より上記の最新確認を優先します。今回Slack自体は更新していません。

## 画面と遷移

| 画面 | 表示・操作 | 次の状態 |
| --- | --- | --- |
| ①タイトル | 「おばけさがし スタンプラリー！」／「ぼうけんを はじめる！」 | あそびかた |
| ②あそびかた | かげを探す→現地のタグにスマホをタッチ→会話を終えて図鑑登録 | 「マップを みる！」で開始済みを保存 |
| ③Map・図鑑 | 良いおばけ9体の場所、晴天・雨天の切り替え、取得カード。未取得のMapマーカー・カードから会話は開始しない | NFC URLから会話へ。終了ボタンで取得カードが飛び出す |
| ④悪いおばけ出現 | 良い9体をすべて集め、最後の取得カードを閉じると暗転し、影が2つ現れる | Mapに2体を追加。どちらからでも現地NFCで会話開始 |
| ⑤メデューサ | 会話＋来場者情報・満足度の4問 | 「メデューサを げんきづける！」で会話終了・取得 |
| ⑥ヴァンパイア | 会話＋感想・改善点の5問 | 「ヴァンパイアに ほうこくする！」で会話終了・取得 |
| ⑦エンディング | 全11体と仲よくなった表示 | 「景品受け取り場所で プレゼントをもらう」で景品提示画面へ |

景品提示画面は「景品受け取り場所に 行って、この画面を みせてね！」と案内します。場所は入口のTV対面壁側です。景品の受渡しを自動記録したり、受領済みと判定したりしません。マップ・図鑑へ戻ることもできます。

開始済みの再訪はMap、全取得済みの再訪はエンディングです。NFC URLがある場合は対象の会話を優先します。解放前の悪いおばけのURLは会話を開かず、Mapで先に良いおばけを集める案内を表示します。URLは処理後に`id`だけを削除し、解放前のタッチは保留・自動再生せず再タッチを必要とします。

取得済みカードからは会話の再閲覧のみ可能です。アンケートを再回答して既存回答を上書きする操作はありません。出現・取得演出はその場の遷移時に表示し、再読み込みで繰り返し強制しません。動きを減らす端末設定ではアニメーションを止めます。

## 晴天・雨天のMap

Mapの表示は天気別に手動で切り替えます。配置の正本は晴天がSlackの確定本文・写真、雨天が依頼者承認済みのCanvaです。屋内はフロアごとの会場図と番号マーカー、屋外は設置場所の目印を一覧で表示します。黒猫2体と悪いおばけ2体は晴天と雨天で設置場所が変わります。初期表示は晴天で、選択は `iufes2026-system-prototype-weather` へ進捗とは別に保存します。スタンプIDと取得条件は共通で、天気を変えても進捗は増減しません。天気予報との自動連携はありません。屋外フランケンの雨天移動は資料に明示されていないため、別の移動先を推測していません。

## 回答仕様

子どもを含む参加者が回答に困って進めなくならないよう、**全問任意・空欄でも会話終了可能**にしました。回答数とラリー達成を分け、未回答を勝手に満足度0点などへ変換しません。

| おばけ・項目 | 入力・選択肢 |
| --- | --- |
| メデューサ：あなたについて | 複数選択：小学生／親子／iU関係者／その他 |
| お祭りを知った場所 | 単一選択：ポスター・チラシ／がっこうのおしらせ／おうちの人・お友達から聞いて／Instagram |
| 今日の満足度 | 単一選択：めっちゃたのしかった！／たのしかった！／ふつうかな |
| 友達におすすめしたいか | 0〜10点の単一選択。初期選択なし。0点も有効な回答 |
| ヴァンパイア：面白かったお店・遊び | 自由記述 |
| 改善したいところ | 自由記述 |
| 次回も来たいか | 単一選択：ぜったい行きたい！／行きたい！／わからない |
| 次回ほしいお店・遊び | 自由記述 |
| 最後のメッセージ | 自由記述 |

- 単一選択には「こたえない」を追加。複数選択はすべて解除、自由記述は空欄で未回答に戻せる。
- 自由記述は各500文字まで（ブラウザーの`maxLength`に合わせUTF-16単位）。前後の空白を除き、空白だけなら未回答。
- 未回答は`null`として記録。無回答でも会話を終えた記録は残る。全問未回答の完了も可能。
- 定義外の選択肢、不正な型、上限超過は受け付けず、修正してから会話を終了する。
- 氏名・連絡先は収集せず、自由記述にも書かないよう案内する。本文はプレーンテキストで扱う。
- 途中で閉じる／Escapeでは取得しない。入力中の内容はページ内だけに保持し、再読み込み時は破棄する。完了ボタンを押した回答だけを端末保存する。
- 完了はおばけごとに1回。再タップ・再保存は冪等にし、同じ回答の重複記録を防ぐ。

現在のフォームは資料の文面・構造を使用しています。資料にある0〜10の表情画像は未提供のため、数値ラベルと両端の説明で選びます。良いおばけの会話と配置は[確定内容](slack-confirmed-content-20261004.md)に基づきます。キャラクターの通常絵11枚・スタンプ絵11枚は10月5日に納品済みです。会話・タイトル・解放は通常絵、取得演出・獲得済み図鑑はスタンプ絵を使い、未発見は仮表示を維持します。黒猫A＝赤い目／B＝青い目はローカル表示用の仮割当で、台詞・設置場所との最終対応は確認中です。

## 保存と完了の関係

現在の実装は**端末内保存のプロトタイプ**です。回答を運営に送信するAPI、中央DB、自動集計はありません。フォームにも端末保存のみであることを表示し、「送信成功」とは表示しません。

会話終了時に進捗と回答を一つのJSONへ保存します。失敗した場合は入力・取得を画面上に保持し、警告を取得カード内とMap等に表示します。再試行で再保存できます。画面を閉じる前に復旧しなければ未保存分は失われます。端末ストレージの削除・プライベートブラウズ終了等による消失や、手動改変を防ぐ機能はありません。

現在の保存キーは `iufes2026-system-prototype-progress-v3-confirmed-20261004` です。データは `schemaVersion: 3`、回答は `version: 2` を維持し、選択肢は表示文言と独立した固定IDを保存します。

| 保存キー | 用途 |
| --- | --- |
| `iufes2026-system-prototype-progress-v3-confirmed-20261004` | 現在の読み書き先 |
| `iufes2026-system-prototype-progress-v3` | 旧5体版v3の移行元。書換・削除しない |
| `iufes2026-system-prototype-progress` | さらに古い版の移行元。書換・削除しない |

```json
{
  "schemaVersion": 3,
  "hasStarted": true,
  "goodStampIds": ["good-01", "good-02", "good-03", "good-04", "good-05", "good-06", "good-07", "good-08", "good-09"],
  "badStampIds": ["bad-01"],
  "surveyResponses": {
    "bad-01": {
      "version": 2,
      "answers": { "visitor": ["elementary", "family"], "discovery": null, "satisfaction": null, "recommendation": "0" }
    }
  }
}
```

悪いおばけの会話完了を`badStampIds`に記録し、回答の有効性から分離します。回答に不備が見つかった場合は警告し、不正な回答は除去しますが、記録済みのスタンプは取り消しません。回答の表示文言と保存形式は別定義です。文言修正では固定ID・過去の回答定義を変更せず、質問や選択肢の意味を変更するときは回答版を追加し、旧版の読み取り処理を残します。

新キーがない場合は、まず旧v3キー `iufes2026-system-prototype-progress-v3` を読み取ります。旧v3キーもない場合は、旧キー `iufes2026-system-prototype-progress` を読み取ります。v2の正しい完了回答は固定IDへ変換し、スタンプも引き継ぎます。v2では旧構成の良い5体（`good-01`〜`good-05`）が揃うことを移行条件として完了回答・悪いスタンプを保持します。旧構成の条件を満たさないv2データからは悪いおばけの完了を引き継ぎません。現行の良い9体の解放条件とは別に扱います。版なしの旧データは良いおばけだけを引き継ぎ、`badVisitedIds`を完了に変換しません。次の保存・再試行で新キーへ保存し、旧キーは変更・削除しません。

新キーへの分離は、旧5体版のv3クライアントが新しい `good-06`〜`good-09` を未知IDとして除去して同じキーへ保存し、新しい進捗を失わせることを防ぐためです。保存形式の番号は変えず、読み書き先を分けて旧版タブの書き込みから保護します。新キー作成後に旧版タブで追加取得した分は自動合成されないため、更新公開後は開いている旧版タブも再読み込みして利用してください。旧キーの削除を伴うロールバックは行わず、新旧の実装を行き来する運用は避けます。

未対応の保存形式・回答版を検出した場合は上書きを止め、再読み込みを案内します。この画面だけに残る未保存分は再読み込みで失われる旨を表示します。保存の直前にも版を確認し、読み込み後に別タブが新しい形式を保存した場合も保護します。

別タブの保存済み進捗は書き込み前、`storage`イベント、画面復帰時（focus・visibilitychange・pageshow）に合成します。同じおばけの回答が衝突した場合は先に保存されたものを優先し、未保存の進捗・別のおばけの回答と入力中の下書きは保持します。解放・完了表示も更新します。画面の自動遷移は同期で新たに開始・全取得となったときだけ行い、進捗が変わらない画面復帰では、参加者が選んだあそびかた・マップ等を維持します。取得カード表示中に別タブで全取得となった場合は、ボタンの文言と遷移先を完了画面へ揃えます。同期だけで自動保存はせず、保存失敗の警告は再試行成功まで残します。ただしlocalStorageに完全な同時書き込み保証はありません。

本番の自動集計を実装する場合は、会話終了と回答の配送状態を分けます。匿名参加ID＋おばけID＋質問版を重複防止キーとし、未送信／送信中／送信済みを管理、サーバーでも質問定義・文字数を検証する構成を想定します。未回答は集計の有効回答数から除き、回答欠損数を別表示します。集計サービス、権限、保持期間、削除方法は公開前に設定・検証する必要があります。現在の端末内回答を無断で自動送信する移行は行いません。
