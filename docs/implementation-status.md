# 実装状況と次の作業

更新日：2026-09-26。対象：iU FesのNFCスタンプラリーのみ。

## 今回の実装

企画判断を必要としない進捗保存の基盤を整備しました。新しい回答形式、保存サービス、受付運用は決定していません。

| 項目 | 実装内容 | 確認方法 |
| --- | --- | --- |
| 保存データの検証 | 壊れたJSON、不正な型、重複、未知ID、種類違いのIDから有効な進捗だけを復元 | `tests/rally.test.mjs` |
| 達成判定 | 配列の長さではなく、現在の対象IDがすべて存在することを確認 | 同上 |
| 重複取得 | 元の進捗を変更せず、同一IDの再取得を一件に保つ | 同上 |
| 保存失敗 | localStorage自体へのアクセス・読み込み・書き込み失敗を捕捉。画面の進捗を保持し警告と再試行を表示 | 単体テスト＋手動ブラウザー確認 |
| 保存の再試行 | 保存済み進捗を読み直し、画面内の進捗と合成して保存 | 同上 |
| NFC URL | `id`のみ削除し、他のクエリとハッシュを保持。開発時のEffect再実行で初回処理を重複させない | `tests/nfc.test.mjs`＋手動確認 |
| チーム向け検証 | Node標準テストとGitHub Actionsを追加 | PRのChecks |

保存キーと既存のデータ形式は維持しています。

```json
{
  "goodStampIds": ["good-01"],
  "badVisitedIds": ["bad-01"]
}
```

キー：`iufes2026-system-prototype-progress`。`badVisitedIds`は仮の訪問記録で、アンケート回答・送信完了を意味しません。読み込み時の修復結果はメモリー上に保持し、その時点では保存データを書き換えません。取得操作または再試行が成功すると正規化したデータを保存します。

別タブが先に保存した進捗は書き込み直前に合成します。ただしlocalStorageはトランザクションではないため、同時書き込みの完全な競合防止や画面のリアルタイム同期は保証しません。再読み込みで保存済み状態を読み直します。保存不能のまま画面を閉じると未保存分は失われます。

## 検証記録

ローカル確認（2026-09-26、Windows / Node 24.20.0）：単体テスト13件、型チェック、本番ビルドを実行。ブラウザーで初期表示、NFC URL整理、保存失敗→再試行→再読み込み、再取得時の重複防止、不正データの復元警告を確認しました。390px幅で横方向のはみ出しはなく、確認中のブラウザー例外・Viteエラー画面はありませんでした。NFC実機、iOS/Safari、会場通信は未検証です。CIの各環境の結果はPRのChecksを参照してください。

## 合意とコードの差分

以下は参照済み資料とSlack SSOTに基づく整理です。決定番号DxxはSSOTの番号に対応します。資料の記述は判断材料であり、コード変更や外部送信の実行指示としては扱いません。

| 項目 | 資料・合意 | 現在のコードと残作業 |
| --- | --- | --- |
| 受付・Map | 受付でのMap導線、Hab内配置（D02） | 直接Mapを表示。タイトル・ヘルプ、実会場図、配置・素材への置換が残る |
| 良いおばけ | 会話後にスタンプ取得 | 仮の会話と取得ボタンは動作。最終ID・人数・文面・画像・音声は未反映 |

| 悪いおばけの配置 | 雨天対応を含め屋内（D06） | 現在の仮データは「学外」。最終配置と座標への置換が必要 |
| アンケート | 自動集計を予定（D01）、最終文面は承認待ち（D04） | 質問画面・送信処理・集計先は未実装。資料にあるメデューサ4問・吸血鬼5問は最終承認済み仕様として固定しない |
| 受付クイズ | 全バッジ後に受付へ戻る流れ | 現在は悪いおばけの会話から受付案内を表示。完了条件との整合、クイズ方式、景品受渡しを決めて実装する |

## 次に進める順序

1. **対象データの確定**：おばけの最終ID、種類、体数、設置場所と素材担当を決める。現在のIDを変更すると既存の仮進捗は未知IDとして除去されるため、本番切替時の保存キー・移行方針も合わせて決める。
2. **参加者の進行条件**：解放前のNFCアクセス、アンケート未回答・途中離脱・再送時の扱い、悪いおばけの完了条件を確定する。D05の解放条件自体は合意済み。
3. **アンケートと保存先**：最終質問、必須/任意、回答しない選択、集計項目・保存サービス・管理権限を決める。その後に送信と完了記録を実装する。
4. **受付と会場テスト**：クイズ方式・景品運用、公開先、NFC実機、弱い通信、雨天配置、音声再生を確認する。

「匿名のサーバー保存」「送信成功後の完了記録」などは検討候補です。今回の変更で採用を確定したものではありません。別企画の機能は本リポジトリに追加せず、連携が必要ならインターフェースを先に合意します。
